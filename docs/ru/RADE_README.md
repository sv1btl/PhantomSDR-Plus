# Цифровой голос RADE v1 для PhantomSDR-Plus

> **Порт 9012.** На станции, настроенной через `install.sh`, sidecar слушает только внутри компьютера, на `PORT_RADE` (9012), а страница обращается к нему как `/rade` на публичном порту 9000 через `proxy.py`, поэтому на маршрутизаторе ничего открывать не нужно.

**RADE** (Radio AutoencoDEr) — флагманский КВ-режим цифрового голоса от FreeDV. Он использует гибрид машинного обучения и ЦОС (нейронный вокодер FARGAN), обеспечивая качественную речь на КВ при отношении сигнал/шум вплоть до −2 дБ в полосе всего 1500 Гц — уже, чем сигнал SSB.

Этот документ описывает полную интеграцию приёма RADE v1 в PhantomSDR-Plus, реализованную в виде sidecar-процесса на Python (`rade_helper.py`), который связывает браузер с цепочкой декодирования `radae_rxe.py` + `lpcnet_demo`.

Он также декодирует **RADE V2 (beta)** — новую форму сигнала FreeDV 3.0 — кнопкой **RADE-v2U**; см. [RADE V2 (beta) — RADE2](#rade-v2-beta--rade2).

## Установка — коротким путём

```bash
cd ~/PhantomSDR-Plus
./install_rade.sh
```

Это и есть вся установка. Сценарий ставит системные пакеты тем менеджером пакетов, который есть на машине (apt, pacman, dnf или zypper), для отсутствующих в дистрибутиве модулей переходит на pip, обновляет `websockets`, если версия из дистрибутива старее нужной sidecar-у 11.0, клонирует и собирает radae, проверяет веса модели, пересобирает фронтенд и запускает sidecar. На Ubuntu 22.04 он передаёт работу `install_rade_ubuntu22.sh`. `./install.sh` предлагает запустить его в рамках обычной установки PhantomSDR-Plus, так что на новой машине RADE уже стоит. Он также собирает rade_c от FreeDV для RADE V2 (beta); если этот шаг не удаётся, RADE V1 всё равно устанавливается.

**Этот документ объясняет, как работает RADE и как им пользоваться.** Установку всегда выполняет `./install_rade.sh` (или `./install.sh`, который её предлагает).

## Как это работает

RADE v1 не может работать в браузере — ему нужны PyTorch и нейронный вокодер FARGAN, слишком большие для WASM. Решение — sidecar-процесс на Python (`rade_helper.py`), работающий на том же сервере, что и PhantomSDR-Plus.

> **Важно:** `freedv_rx` из репозитория codec2 **не** поддерживает RADEV1. Цепочка декодирования RADE целиком находится в отдельном репозитории `radae` Дэвида Роу (VK5DGR). Не пытайтесь использовать `freedv_rx` из codec2 для RADE.

Когда вы выбираете RADE в браузере:

1. Веб-интерфейс задаёт базовую демодуляцию USB или LSB — сервер на C++ демодулирует сигнал SSB как обычно.
2. Необработанный демодулированный PCM снимается в `audio.js` **до** любого отключения звука или шумоподавителя — `radae_rxe.py` нужен непрерывный входной поток, чтобы удерживать кадровую синхронизацию.
3. Каждый блок PCM дополняется нулями из вещественного f32 в комплексный f32 (вещественная часть + 0.0 мнимой) — именно этого `radae_rxe.py` ожидает на стандартном входе.
4. Sidecar передаёт эти отсчёты в `radae_rxe.py`, который выдаёт признаки вокодера.
5. `lpcnet_demo -fargan-synthesis` преобразует признаки в речь s16 с частотой 16000 Гц.
6. Sidecar преобразует s16 → f32 и отправляет результат обратно в браузер двоичными кадрами WebSocket.
7. Браузер воспроизводит декодированную речь через Web Audio API на 16000 Гц.

Сервер на C++ (`spectrumserver.cpp`) при этом вообще не изменяется.

## RADEL против RADEU

RADE v1 всегда передаётся по SSB. По соглашению:

| Режим | Боковая полоса | Использовать на диапазонах                |
|-------|----------------|-------------------------------------------|
| RADEL | LSB            | 160 м, 80 м, 40 м  (≤ 10 МГц)            |
| RADEU | USB            | 20 м, 17 м, 15 м, 12 м, 10 м (> 10 МГц)  |

## RADE V2 (beta) — RADE2

**RADE V2** — новая форма сигнала FreeDV 3.0: шириной около 800 Гц вместо 1500 Гц, без пилот-символов и примерно на 3 дБ чувствительнее при низком SNR. **У FreeDV она пока в бета-версии** — её передают только станции, тестирующие FreeDV 3.0, и до выпуска сигнал ещё может измениться. PhantomSDR-Plus декодирует её рядом с RADE V1:

| Кнопка | Версия | Боковая полоса | Фильтр |
|---|---|---|---|
| **RADE-v2U** (RADE2) | RADE V2 (beta) | USB на всех диапазонах | 1040–1930 Hz |
| **RADE-v1L** / **RADE-v1U** (RADEL / RADEU) | RADE V1 | LSB / USB | 700–2200 Hz |

V2 декодируется на сервере портом FreeDV на C — **rade_c** (`radae_rx --v2` и его собственный `lpcnet_demo`), собранным в отдельной папке `~/rade_c`, так что установка V1 в `~/radae` никогда не затрагивается. `./install_rade.sh` загружает и собирает его (шаг «rade_c (RADE V2, beta)»); если этот шаг не удаётся, он лишь предупреждает, а RADE V1 всё равно устанавливается. `rade_helper.py` использует rade_c начиная со следующего подключения RADE2 — перезапуск не нужен, — а без него RADE2 сообщает слушателю «RADE V2 is not installed on this station yet». Декодирование V2 стоит около 1 % одного ядра CPU на слушателя (V1: около 70–80 %).

**В эфире**

- Настраивайтесь не дальше примерно **±30 Гц** от частоты станции. Дальше V2 по-прежнему показывает «Synced», но речь неразборчива.
- Каждая передача начинается с задержкой **2–3 с**: пока V2 синхронизируется, он сохраняет сигнал, а затем воспроизводит начало передачи.
- Ниже примерно **−2 дБ SNR** звук V2 отключается, а панель показывает «Searching for signal…» — если только последние 2 секунды не похожи на настоящий V2 (декодер большую часть времени видит свой сигнал, а его оценка частоты остаётся стабильной); тогда звук идёт примерно до **−6 дБ**. На загруженных частотах телефонии LSB, прослушиваемых в USB (40 м), V2 может синхронизироваться на обычные голоса и воспроизводить неразборчивый звук; они никогда не выглядят стабильными, поэтому остаются без звука. Оба порога задают `RADE_V2_MIN_SNR` и `RADE_V2_WEAK_SNR`.
- Между передачами панель возвращается к «Searching for signal…».

**Когда выйдет FreeDV 3.0**, снова запустите `./install_rade.sh` — или `git pull` в `~/rade_c` и `cmake --build build`, — и новые подключения RADE2 будут использовать новую версию.

## Управление sidecar

**Отдельный управляющий сценарий для RADE обычно не нужен.** Пусковые сценарии приёмника (`start-rx888mk2.sh`, `start-airspyhf.sh`, `start-rtl.sh`, `start-rsp1a.sh`, `start-fobos-hf.sh`, `start-fobos.sh`, `start-hackrf.sh`) сами запускают sidecar, как только сервер подтверждённо работает, перезапускают его при завершении и сообщают его состояние в итоговой строке — `✔ RADE sidecar running` либо пометка `·` с объяснением, почему он не был включён (не установлен, `RADE_ENABLED=0` или нет `python3`). `./stop-websdr.sh` останавливает его вместе с сервером. Чтобы запустить сервер без RADE, стартуйте его с `RADE_ENABLED=0`.

`rade.sh` остаётся для автономного применения — запуска sidecar без пускового сценария PhantomSDR-Plus или его отдельной проверки:

```bash
chmod +x ~/PhantomSDR-Plus/rade.sh
cd ~/PhantomSDR-Plus
./rade.sh start      # start sidecar with self-restarting watchdog
./rade.sh stop       # stop sidecar + watchdog + all lpcnet_demo children
./rade.sh restart    # stop then start cleanly
./rade.sh status     # show running / stopped + process info
```

Активность sidecar записывается в `~/PhantomSDR-Plus/rade.log`:

```bash
tail -f ~/PhantomSDR-Plus/rade.log
```

> **Не смешивайте эти два способа, пока сервер работает.** Если сторож пускового сценария активен, он вернёт sidecar примерно за пять секунд, и `./rade.sh stop` будет выглядеть как неудача. Чтобы остановить RADE при работающем сервере, либо запускайте сервер с `RADE_ENABLED=0`, либо остановите всё командой `./stop-websdr.sh`.

> Если вы всё же запускаете `rade.sh` автономно, **всегда используйте `./rade.sh stop`** — один лишь `pkill -f rade_helper.py` не пересилит его собственного сторожа, который возрождает процесс за 3 секунды.

## Порт 9012

Sidecar слушает TCP-порт **9012**, только внутри компьютера. Браузер обращается к нему через `proxy.py` как `/rade` на публичном порту 9000, поэтому открывать другие порты на маршрутизаторе или в брандмауэре не нужно.

```bash
# Is the sidecar listening?
ss -tlnp | grep 9012
```

## Использование RADE в браузере

1. Откройте веб-интерфейс PhantomSDR-Plus
2. Найдите активные станции на **[qso.freedv.org](https://qso.freedv.org)**
3. Настройтесь на частоту станции по шкале
4. В **Decoder Options** выберите:
   - **RADE v2 · RADE2** для RADE V2 (beta), USB на всех диапазонах
   - **RADE v1 — RADEL (LSB)** для 40 м / 80 м / 160 м
   - **RADE v1 — RADEU (USB)** для 20 м / 17 м / 15 м / 12 м / 10 м
5. Нажмите **Decoder: ON**

### Кнопки RADE-v1L / RADE-v1U (в одно нажатие)

Шаги 4 и 5 можно заменить одним нажатием. Пара кнопок **RADE-v1L** / **RADE-v1U** доступна в трёх местах:

- рядом с заголовком **Modes** на главной панели;
- внутри всплывающего окна **Modes**;
- внутри всплывающего окна **Bands**.

Нажатие выбирает декодер, переводит декодер в ON, закрывает всплывающее окно, из которого вы нажали, и прокручивает панель RADE в поле зрения. Кнопка остаётся синей, пока RADE работает. **Повторное нажатие той же кнопки выключает RADE** — панель закрывается, а вид модуляции и полоса пропускания возвращаются к значениям, описанным ниже. Кнопки, выпадающий список **Decoder Options** и кнопка ON/OFF используют одно и то же состояние.

Кнопка **RADE-v2U** стоит перед RADE-v1L и RADE-v1U в тех же трёх местах (и кнопка RADE2 на `/mobile`); она запускает RADE V2 (beta) в USB — см. [RADE V2 (beta) — RADE2](#rade-v2-beta--rade2).

### Состояния индикатора панели

| Индикатор | Значение |
|---|---|
| 🔴 Красный — «Connecting to sidecar…» | Порт 9012 недоступен или sidecar не запущен |
| 🟡 Жёлтый — «Searching for signal…» | Sidecar подключён, кадр RADE ещё не обнаружен |
| 🟢 Зелёный — «Synced · SNR x.x dB» | Идёт декодирование — воспроизводится речь |

### Когда вы выключаете декодер

Режим и полоса автоматически возвращаются к правильному значению по умолчанию для текущей частоты, заданному в `bands-config.js`, — точно так же, как у FAX, NAVTEX, FSK.

## Проверка и отладка

### Работает ли sidecar?

```bash
ps aux | grep rade_helper | grep -v grep
ss -tlnp | grep 9012
```

### Наблюдение за активностью в реальном времени

```bash
tail -f ~/PhantomSDR-Plus/rade.log
```

При подключении браузера:
```
[RADE] client connected: x.x.x.x:XXXXX
[RADE] x.x.x.x:XXXXX  sps=12000 sideband=LSB
[RADE] x.x.x.x:XXXXX spawning pipeline (torch_threads=1)
```

### Консоль браузера (F12)

```
[RADE] ▶ ENABLED LSB @ 12000 Hz → helper ws://localhost:9000/rade
```
Хорошо — WebSocket открыт. Значение в Гц соответствует `audioOutputSps` вашего сервера (обычно 8000–12000 Гц).

```
[RADE] sidecar socket error
```
Sidecar недоступен — проверьте, что он запущен (`ss -tlnp | grep 9012`) и что запущен `proxy.py`.

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `RADE_HELPER_PORT` | `9012` | TCP-порт, который слушает sidecar |
| `RADE_HELPER_HOST` | `0.0.0.0` | Адрес привязки (`127.0.0.1` за прокси) |
| `RADAE_DIR` | `~/radae` | Корень репозитория radae |
| `RADE_MODEL` | `RADAE_DIR/model19_check3/checkpoints/checkpoint_epoch_100.pth` | Веса модели |
| `LPCNET_DEMO` | `RADAE_DIR/build/src/lpcnet_demo` | Исполняемый файл lpcnet_demo |
| `RADE_AUXDATA` | `1` | Установите `0`, чтобы передать `--noauxdata` в `radae_rxe.py` |
| `RADE_TORCH_THREADS` | `1` | Потоки PyTorch/OpenBLAS на экземпляр `radae_rxe.py` — ограничивает нагрузку на ЦП |
| `RADE_PIN_CORES` | `1` | Привязывает каждую цепочку декодирования к своему набору ядер; `0` отключает привязку |
| `RADE_CORES_PER_CLIENT` | `2` | Ядер на клиента при включённой привязке |
| `RADE_C_DIR` | `~/rade_c` | Корень rade_c (RADE V2) |
| `RADE_C_RX` | `RADE_C_DIR/build/src/radae_rx` | Программа приёма rade_c |
| `RADE_C_LPCNET` | `RADE_C_DIR/build/src/lpcnet_demo` | Собственный lpcnet_demo rade_c |
| `RADE_V2_MIN_SNR` | `-2` | Ниже этого SNR (дБ) звук V2 отключается |
| `RADE_V2_WEAK_SNR` | `-6` | До этого SNR (дБ) V2 продолжает звучать, пока сигнал похож на настоящий V2; задайте `RADE_V2_MIN_SNR` или выше, чтобы это отключить |
| `RADE_V2_TARGET_DB` | `-16` | Уровень, к которому приводится речь V2, в dBFS (`0` = выкл.) |

## Устранение неполадок

### Красный баннер — «Sidecar not reachable»

```bash
# Is sidecar running?
ps aux | grep rade_helper | grep -v grep

# Start it manually for testing
python3 ~/PhantomSDR-Plus/rade_helper.py &
```

---

### `lpcnet_demo: No such file or directory`

Сборка radae не завершилась. Соберите заново:

```bash
cd ~/radae/build
cmake .. && make -j$(nproc)
ls src/lpcnet_demo     # should exist now
```

---

### Жёлтый индикатор — «Searching for signal» — синхронизация не наступает

- Убедитесь в правильной боковой полосе: RADEL для ≤ 10 МГц, RADEU для > 10 МГц
- Проверьте на [qso.freedv.org](https://qso.freedv.org), что станция сейчас передаёт
- RADE v1 использует 30 несущих в полосе 1500 Гц — на водопаде выглядит компактной группой
- Дайте до 1,5 секунды на захват

### Несколько одновременных пользователей

Каждое подключение браузера порождает собственную независимую пару `radae_rxe.py` + `lpcnet_demo`, поэтому каждый пользователь может свободно настраиваться на свою частоту.

По умолчанию `radae_rxe.py` использует **все доступные ядра ЦП** для матричных операций PyTorch, из-за чего нагрузка достигает ~900 % на экземпляр. `rade_helper.py` ограничивает это двумя оптимизациями:

1. `OMP_NUM_THREADS=1` (и аналоги для MKL/OpenBLAS) — ограничивает PyTorch одним потоком
2. Векторизованные с помощью numpy функции преобразования звука — убирают накладные расходы циклов Python

Результат: каждый экземпляр использует примерно **8–10 %** одного ядра, чего достаточно для декодирования RADE в реальном времени. Если слышны выпадения звука, увеличьте до 2 потоков:

```bash
RADE_TORCH_THREADS=2 ./start-rx888mk2.sh     # or your receiver's launcher
# standalone: RADE_TORCH_THREADS=2 ./rade.sh restart
```

| Одновременных пользователей RADE | Примерная нагрузка на ЦП |
|---|---|
| 1 | ~9 % |
| 5 | ~45 % |
| 10 | ~90 % |
| 20 | ~180 % |

На i5-12450H (12 потоков), где spectrumserver занимает ~42 %, а rx888_stream ~11 %, у вас остаётся около **1000 % запаса** — этого хватит на **20 и более одновременных** пользователей RADE, прежде чем ЦП станет проблемой.

## Обновление RADE v1

**Чтобы обновить RADE, снова запустите `./install_rade.sh`.** Он загружает последние версии radae и rade_c, пересобирает их и перезапускает sidecar; сам приёмник перезапускать не нужно.

---

*Разработано и проверено на PhantomSDR-Plus (форк sv1btl/PhantomSDR-Plus) с RX-888 MK2 на Ubuntu 24.04. Сервер на C++ не изменяется.*

*RADE разрабатывают David Rowe VK5DGR и команда FreeDV.* *См. [freedv.org/radio-autoencoder](https://freedv.org/radio-autoencoder).*

### Полное удаление и чистая переустановка

Вот полный демонтаж перед повторным запуском install_rade.sh:
1. Остановите sidecar cd ~/PhantomSDR-Plus && ./rade.sh stop
2. Удалите репозиторий radae и сборку rm -rf ~/radae
3. Удалите torch (установлен в локальный каталог пользователя) pip3 uninstall -y torch rm -rf ~/.local/lib/python3.11/site-packages/torch*
4. Удалите пакеты Python из apt (необязательно — пропустите, если их используют другие программы) sudo apt-get remove -y python3-numpy python3-scipy python3-matplotlib python3-websockets sudo apt-get autoremove -y
5. Убедитесь, что всё удалено python3 -c "import torch" 2>&1        # should say ModuleNotFoundError ls ~/radae 2>&1                        # should say No such file or directory
6. Чистая установка chmod +x ~/PhantomSDR-Plus/install_rade.sh ~/PhantomSDR-Plus/install_rade.sh
