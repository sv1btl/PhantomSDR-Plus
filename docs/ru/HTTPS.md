# Безопасный доступ — https://

Станция PhantomSDR-Plus может быть доступна по **https://**, а не только по http://. Браузер тогда показывает замок, соединение шифруется, и браузеры разрешают странице свой лучший путь для звука (AudioWorklet), в котором они отказывают обычным страницам http. Адрес http продолжает работать в точности как раньше, бок о бок.

Этим занимается **Caddy** — небольшой веб-сервер, который ставится перед приёмником на порт 443. Caddy получает бесплатный сертификат от **Let's Encrypt** для DNS-имени вашей станции и сам обновляет его раз в несколько месяцев, без какого-либо участия с вашей стороны.

---

## Что нужно

| | |
|---|---|
| **DNS-имя** | Let's Encrypt сертифицирует имена, а не голые IP-адреса. Подойдёт бесплатное имя динамического DNS (no-ip, DuckDNS, dynu и подобные), указывающее на ваш публичный адрес, причём адрес может меняться — имя следует за ним. |
| **Ещё два порта на роутере** | Пробросьте TCP **443** (https) и TCP **80** на компьютер приёмника, вдобавок к вашему публичному порту (9000). Порт 80 нужен только для того, чтобы доказать Let's Encrypt, что имя ваше, при выдаче и обновлении сертификата. |
| **Станция, настроенная с вопросами о станции** | Должен существовать `station.conf`. На станции, установленной до вопросов о станции, сначала один раз выполните `bash configure-station.sh` — он предложит порты, которые ваша станция уже использует, так что ничего не сдвинется. |

## Включение

### При установке

Среди вопросов о станции, в группе **Internet**, ответьте «да» на:

```
  Also serve the receiver over https://? [y/N]: y
```

Установщик ставит Caddy, получает сертификат и в конце показывает оба адреса.

### На уже работающей станции

```bash
cd ~/PhantomSDR-Plus
bash setup-https.sh
```

Скрипт читает ваше DNS-имя из `station.conf`, устанавливает Caddy (из вашего дистрибутива; в Ubuntu 22.04 — из собственного репозитория Caddy), направляет его на приёмник, пересобирает страницу, чтобы она ссылалась на свой адрес https, перезапускает proxy и ждёт сертификат. Ответ «да» на вопрос о https в `bash configure-station.sh` делает ровно то же самое.

По завершении:

```
  ✔ https://myname.ddns.net/ is live

  https://myname.ddns.net/   — and http://myname.ddns.net:9000/ as before
```

### Проверка и отключение

```bash
bash setup-https.sh --status    # включено ли, и отвечает ли сертификат?
bash setup-https.sh --remove    # отключить https; http остаётся в точности как есть
```

Если позже сменить DNS-имя через `bash configure-station.sh`, Caddy сам перейдёт на новое имя.

## Как это работает

```
  visitor ──https──► Caddy :443 ──► proxy.py :9014 (this computer only) ──► spectrumserver, panel, RADE …
  visitor ──http───────────────────► proxy.py :9000 ───────────────────────► the same
```

| Порт | Что | Открыт на роутере |
|---|---|---|
| 443 | Caddy — https | да |
| 80 | Caddy — проверка сертификата и перенаправление на https | да |
| 9000 | proxy.py — http, как раньше | да |
| 9014 | proxy.py — сюда Caddy передаёт посетителей | нет — внутри компьютера |

Caddy обращается к proxy через отдельный порт, потому что иначе, с точки зрения proxy, каждый посетитель, пришедший через Caddy, приходил бы с самого компьютера, — а запросу с самого компьютера доверяют: он может отключать слушателей и не учитывается в ограничениях по IP. На порту 9014 proxy берёт у Caddy настоящий адрес посетителя и никогда не считает посетителя локальным, поэтому список слушателей, ограничения по IP и kick сисопа работают в точности как через http, и никто не может выкинуть слушателя через https.

---

## Что меняется для слушателей

- **Работают оба адреса.** Каталоги и карта websdr.org продолжают показывать адрес http; обратный вызов websdr.org и клиенты Kiwi используют http.
- **Звук лучше через https.** Браузеры дают защищённой странице AudioWorklet — более стабильный путь для звука, чем тот, которым вынуждены пользоваться обычные страницы http.
- **Receive Diversity с партнёрами только на http.** Браузер не позволяет странице https открывать обычные соединения `ws://`, поэтому со страницы https нельзя добавить станцию-партнёра, у которой есть только http; партнёры с https работают, а партнёры WebSDR работают через relay. Для партнёра только на http используйте адрес http страницы.
- **Управление трансивером (TCI-CAT).** Соединения с `127.0.0.1` на собственном компьютере слушателя разрешены со страницы https в актуальных Chrome, Edge и Firefox.

## Только в локальной сети — `--lan`

Без DNS-имени https всё равно можно использовать дома:

```bash
bash setup-https.sh --lan
```

Тогда Caddy выпускает собственный сертификат для локального адреса и имени компьютера. Браузеры этот сертификат не знают и в первый раз предупреждают; примите его или сделайте так, чтобы ваши компьютеры доверяли корневому сертификату Caddy:

- на самом компьютере приёмника: `sudo caddy trust`
- на другом компьютере: скопируйте с приёмника `/var/lib/caddy/.local/share/caddy/pki/authorities/local/root.crt` (точный путь показывает `sudo caddy environ`, в `caddy.AppDataDir`) и импортируйте его в браузер или систему как доверенный центр сертификации.

## На этом компьютере уже работает веб-сервер

Если nginx, Apache или другая настройка Caddy уже занимает порт 443 или 80, `setup-https.sh` его не перехватывает: он останавливается и показывает, что добавить в ваш сервер. Для nginx — внутри блока `server { … }` вашего https-сайта:

```nginx
location / {
    proxy_pass http://127.0.0.1:9014;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_read_timeout 1d;
}
```

Для Apache (с `mod_proxy`, `mod_proxy_http` и `mod_proxy_wstunnel`):

```apache
ProxyPass        / http://127.0.0.1:9014/ upgrade=websocket
ProxyPassReverse / http://127.0.0.1:9014/
```

Затем отметьте станцию как https в `station.conf`, чтобы proxy открыл порт 9014, а страница ссылалась на свой адрес https, — мастер ещё раз сообщит, что порт занят, это ожидаемо:

```bash
STATION_HTTPS=y bash configure-station.sh
```

## Устранение неполадок

| Признак | Что проверить |
|---|---|
| `no certificate yet` | DNS-имя должно указывать на ваш публичный адрес (`ping myname.ddns.net` из-за пределов вашей сети), а роутер должен пробрасывать 443 и 80 на этот компьютер. Caddy сам продолжает попытки; его журнал: `sudo journalctl -u caddy -n 50`. |
| Провайдер блокирует порт 80 | Caddy умеет доказывать имя и только через порт 443, так что обычно достаточно 443; по возможности оставьте 80 проброшенным. |
| `too many failed authorizations` в журнале Caddy | Let's Encrypt допускает лишь несколько неудач в час. Устраните причину, подождите час, затем `sudo systemctl restart caddy`. |
| https работает дома, но не снаружи | Роутер пробрасывает 443 на другой компьютер или не пробрасывает вовсе. |
| Список слушателей или панель пользователей пусты через https | Один раз выполните `bash configure-station.sh` и согласитесь на пересборку: страница должна знать свой адрес https. |
| `Port 443 is already used by another web server` | См. выше *На этом компьютере уже работает веб-сервер*. |
